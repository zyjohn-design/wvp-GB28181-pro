# 文档维护与交付

[文档入口](../第三方对接接口手册.md) · [AI对接指南](AI对接指南.md)

## 文件职责

| 文件 / 目录 | 维护方式 | 用途 |
|---|---|---|
| 接入指南.md | 人工维护 | 业务流程、跨接口语义、现场要求 |
| AI对接指南.md | 人工维护 | AI读取顺序、编码、ID映射、完整流程与结果判断 |
| 维护说明.md | 人工维护 | 生成、校验、交付约定 |
| ../第三方对接接口手册.md | 自动生成 | 小体积统一入口 |
| 模块索引.md、接口索引.md、模型索引.md | 自动生成 | 导航，无全量字段表 |
| modules/*.md | 自动生成 | 每个Controller的路由目录 |
| routes/*.md | 自动生成 | 每条方法+路径对应一页，含参数、响应、示例和关联模型 |
| models/*.md | 自动生成 | 每个源码模型单独一页，含继承字段与关联模型 |
| route-index.json | 自动生成 | 方法、路径、参数摘要、源码和文档文件的机器检索索引 |

## 修改与生成

在仓库根目录执行：

```bash
python3 scripts/generate-complete-api-manual.py
python3 scripts/validate-api-docs.py
```

先修改Controller、参数/模型注释或生成器中的已确认业务规则，再重新生成；同时更新人工维护的业务说明。不要只编辑routes、models、modules里的输出，重新生成会覆盖。生成器只清理这三个专用目录中过期的Markdown文件，不清理人工指南。

接口文件名使用HTTP方法和完整路径的稳定摘要，新增其他路由不会导致所有链接变化。同名模型按源码路径区分。字段表保留“源码未声明”，避免把源码索引误当成已经审计过的完整业务约束。

`scripts/generate-api-reference.py`仍作为源码解析器被导入；它单独运行时生成的是历史静态索引，不是新对外入口。新文档统一使用上面的生成命令。

## 体积与读取策略

原单文件约3MB、5.2万行，编辑器需要同时渲染全部字段表。拆分后入口只保留导航；接口和模型按需打开。总文档量不必减少，单次读取量会显著降低，也便于AI准确选择上下文。

交付时一起提供 `doc/第三方对接接口手册.md` 和完整 `doc/api/` 目录，保留相对目录结构。仅发入口文件会导致链接失效。需要某项业务时，可把入口、AI指南、对应业务说明、用到的接口与关联模型发给对接方；如果裁剪，应保留链接依赖。

不在默认入口嵌入完整文档，也不自动拼出新的巨型Markdown。离线阅读可直接打开目录中的Markdown；托管静态站点时应按页面加载，保留相对链接。
