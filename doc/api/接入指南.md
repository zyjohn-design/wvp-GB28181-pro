## 1. 接入前准备与标识

部署方应给对接方提供以下配置，不能直接照抄其他现场的端口或地址。

| 配置 | 示例占位符 | 用途 |
|---|---|---|
| Web/API 根地址 | `https://<wvp-host>` | 本文所有 `/api/...` 路径的前缀 |
| 媒体服务外部地址 | 由点播结果返回 | RTSP、FLV、FMP4、HLS、WebRTC 等播放；可能与 API 主机不同 |
| SIP 地址、端口、传输方式 | `<sip-host>:<sip-port>`，UDP/TCP | GB28181 设备或下级平台注册 |
| RTP 收流地址与端口范围 | 以 INVITE SDP 或收流接口返回为准 | GB28181 或第三方 RTP/PS 媒体传输 |
| 凭证 | `api-key` 或登录获取的 `access-token` | HTTP API 鉴权 |
| 媒体鉴权、网关映射 | 按现场配置 | 某些推流播放要求签名、`callId` 或代理规则 |

**三种 ID 不可混用：**

| 名称 | 类型与来源 | 传入哪些接口 |
|---|---|---|
| `deviceId` | 国标设备/下级平台编号，来自 [GET /api/device/query/devices](routes/get-08dbae62822e.md)（[模块条目](modules/DeviceQuery.md#route-get-08dbae62822e)） 的 `data.list[].deviceId` | `/api/play/**`、`/api/front-end/**` 等路径 |
| 国标 `channelId` | 国标通道编号，来自设备通道列表 `data.list[].deviceId` | 直连点播、回放、云台接口的 `{channelId}` |
| 通用通道 `gbId` | 数据库整数 ID，来自 [GET /api/common/channel/list](routes/get-4a6977eb4970.md)（[模块条目](modules/ChannelController.md#route-get-4a6977eb4970)） 的 `data.list[].gbId` | `/api/common/channel/**` 的 `channelId` 查询参数 |

`CommonGBChannel.gbDeviceId` 是该通道的国标编号；它不是 `gbId`。`StreamContent.stream` 是媒体流 ID；它也不是通道 ID。客户端应保存点播接口返回的 `app`、`stream`、`mediaServerId`，回放停止、录像查询及媒体排错时会用到。

## 2. 鉴权、请求与统一响应

### 2.1 认证

| 方式 | 请求 | 说明 |
|---|---|---|
| JWT 登录 | [POST /api/user/login](routes/post-ca71551a070c.md)（[模块条目](modules/UserController.md#route-post-ca71551a070c)），表单或查询参数 `username`、`password` | `password` 是密码的 32 位 MD5 值；成功后从 `data.accessToken` 或响应头 `access-token` 取 JWT |
| JWT 使用 | 请求头 `access-token: <JWT>` | 适合有登录会话的应用；令牌过期后重新登录 |
| API Key | 请求头 `api-key: <API_KEY>` | 适合服务到服务调用；由管理员发放、启用并设置权限，不要放进 URL |

| 字段 | 位置 | 类型 | 必填 | 格式 / 要求 | 默认值 / 未传行为 | 说明 | 示例 |
|---|---|---|---|---|---|---|---|
| `username` | 登录Query / Form | string | 是 | 已存在的用户名 | 无 | 登录账号 | `<username>` |
| `password` | 登录Query / Form | string | 是 | 密码的32位MD5字符串 | 无 | 按登录接口约定编码 | `<32位MD5>` |
| `access-token` | Header | string | 二选一 | 有效JWT | 无 | 与api-key选择一种；过期重新登录 | `<JWT>` |
| `api-key` | Header | string | 二选一 | 管理员发放并启用的API Key | 无 | 服务间身份凭证 | `<API_KEY>` |
| `data.accessToken` | 登录响应 | string | 输出字段 | JWT字符串 | 不适用 | 登录成功时读取 | `<JWT>` |

```bash
WVP='https://<wvp-host>'
API_KEY='<由部署方发放的密钥>'
curl -sS "$WVP/api/common/channel/list?page=1&count=20" -H "api-key: $API_KEY"
```

默认读接口需要有效身份；写操作以及虽然使用 GET 的设置、云台、预置位等控制操作通常需要 `ADMIN` 或 `OPERATOR`。某个部署可能在 `interface-authentication-excludes` 中放行特定路径，**对接方不能假设其他部署也已放行**。管理 API Key 需要管理员权限。HTTP 媒体 URL 的认证与 WVP API 认证是两套机制，按媒体服务与现场配置判断。

### 2.2 请求编码与返回

- 路径、查询参数使用 URL 编码；中文名称和时间中的空格要正确编码。标注 JSON body 的接口发送 `Content-Type: application/json`。
- 控制接口多为 GET，但会改变设备状态；不要预取、缓存或在网络失败后盲目重试。
- 普通 JSON 接口返回 `WVPResult<T>`；文件下载、媒体流、内部 Hook 与兼容接口可能不同。

```json
{"code":0,"msg":"成功","data":{"gbId":123}}
```

| 响应字段 | 类型 | 可空 / 出现条件 | 格式 / 取值 | 说明 | 示例 |
|---|---|---|---|---|---|
| `code` | integer | 统一响应时提供 | 0成功；非0失败 | 常见100通用失败、400参数错误、401未登录、403无权限、404未找到、408/486超时、500系统异常；可有设备或媒体错误码 | `0` |
| `msg` | string | WVPResult中为非空说明 | 人可读结果或错误原因 | 失败时展示并记录，不只看HTTP状态 | `"成功"` |
| `data` | object / array / string / null | 按具体接口；允许null时见对应表 | 业务结果结构 | void控制接口通常为null；按接口类型解码 | `null` |

先检查 HTTP 状态，再检查 `code`；业务错误可能仍使用 HTTP 200。成功的点播表示已拿到可用流信息，普通控制请求的成功含义依接口约定；预置位设置、调用、删除须收到 SIP `200 OK` 才返回 `code=0`，表示设备已接收指令，不能据此认定镜头到位或设备已永久保存。修改平台名称备注的成功只表示备注保存完成。文件响应应按 `Content-Type` 处理，不要强行解析 JSON。

错误处理约定：统一 `WVPResult` 的 `msg` 不为空；有具体原因时原样返回，没有原因时使用错误码对应说明，未知码使用“请求失败，错误码：…”。缺失参数、类型错误、无效云台 `command` 均返回明确提示。WVP 页面通过统一请求拦截器弹出业务错误、HTTP 错误和最终网络错误；第三方页面也应展示 `msg`。认证失效按重新登录提示处理。文件、流、内部 Hook、兼容接口等不使用统一结构的响应仍按各自约定处理。

例如：`zoomSpeed=16` 返回 `{"code":100,"msg":"zoomSpeed 为 0-15的数字","data":null}`。省略 `zoomSpeed` 时默认 `1`（修复前版本错误地使用 `16`，升级前请显式传 `zoomSpeed=1`）。直连接口与统一接口速度范围不同，见第 8.1 节。

分页接口的 `data` 通常是 `PageInfo<T>`，字段如下。判断空页应检查 `list.length`。

| 响应字段 | 类型 | 格式 / 取值 | 出现条件 / 可空 | 说明 | 示例 |
|---|---|---|---|---|---|
| `data.list` | array | T对象数组 | 分页成功时读取 | 本页记录；空页为[] | `[]` |
| `data.pageNum` | integer | 页码，从1开始 | 分页成功时读取 | 当前页 | `1` |
| `data.pageSize` | integer | 整数 | 分页成功时读取 | 每页容量 | `20` |
| `data.total` | integer | 记录数 | 分页成功时读取 | 所有页总记录数 | `105` |
| `data.pages` | integer | 页数 | 分页成功时读取 | 总页数 | `6` |
| `data.size` | integer | 记录数 | 分页成功时读取 | 本页实际记录数 | `20` |
| `data.hasNextPage` | boolean | true / false | 分页成功时读取 | 是否有下一页 | `true` |
| `data.hasPreviousPage` | boolean | true / false | 分页成功时读取 | 是否有上一页 | `false` |

### 2.3 字段表阅读规则

| 列 / 标记 | 含义 |
|---|---|
| 位置 | Path为路径参数；Query / Form为查询串或表单；JSON Body为JSON请求体；Header为请求头 |
| 必填“是” | 必须提供；即使Spring绑定注解允许缺省，已确认的业务校验要求仍列为必填 |
| 必填“否” | 允许不传；是否可以传空字符串取决于该字段的格式和业务规则 |
| 必填“源码未声明” | 未从源码确认，不能直接理解为可选；需结合接口业务校验 |
| 格式 / 范围 / 可选值 | 按源码注释或已核对的业务规则列出；未声明时不臆造长度、枚举或单位 |
| 默认值 / 未传行为 | 请求不传时的处理；标有“Java初始值”的是模型初值，不等同于所有接口的默认值 |
| 响应可空 / 出现条件 | 说明输出字段是否可能为null或被省略，不表示请求必填 |
| 示例 | 仅演示数据形状，不表示真实设备、有效凭证或全部校验条件 |

## 3. 视频协议与网络要求

**先取得点播接口返回的媒体 URL，再选择客户端支持的字段；不要按经验拼接端口、路径或流 ID。** 同一路媒体可以有多种播放协议，但实际非空字段取决于流媒体节点是否开启对应协议、外部端口是否可达以及编码兼容性。

| 协议/传输 | 数据方向 | 接口或返回字段 | 客户端与注意事项 |
|---|---|---|---|
| GB28181 SIP + RTP/PS | 设备/下级平台 → WVP | 设备注册、目录、INVITE；`/api/play/start/...` | SIP 是信令；RTP/PS 是媒体承载，不是浏览器直接播放 URL。收流 IP/端口以 SDP 为准 |
| RTSP / RTSPS | 摄像头 → WVP 拉流，或 WVP → 播放器 | 代理 `srcUrl`；播放 `rtsp`/`rtsps` | 适合 VLC、FFplay、服务端；浏览器通常不直接播放 RTSP。RTSP over TCP/UDP 应与现场网络一致 |
| RTMP / RTMPS | 推流端 → 媒体节点，或媒体节点 → 播放器 | `rtmp`/`rtmps` | 主要供推流工具或专用客户端；推流 URL 和鉴权签名由部署方提供 |
| HTTP-FLV / HTTPS-FLV | 媒体节点 → 播放器 | `flv`/`https_flv` | 浏览器通常需 FLV 播放器库；HTTPS 页面使用 HTTPS 地址 |
| WS-FLV / WSS-FLV | 媒体节点 → 播放器 | `ws_flv`/`wss_flv` | HTTPS 页面使用 WSS；WebSocket 代理须正确完成 101 协议升级 |
| FMP4 | 媒体节点 → 播放器 | `fmp4`/`https_fmp4` 等 | `.live.mp4` 是流式 FMP4，不等同于可下载的完整 MP4 录像文件 |
| HLS | 媒体节点 → 播放器 | `hls`/`https_hls` 等 | `.m3u8`，兼容性较好但通常有更高延迟；检查切片 URL 是否可达 |
| HTTP-TS / WS-TS | 媒体节点 → 播放器 | `ts`/`https_ts`/`ws_ts` 等 | 按客户端解复用能力选择 |
| WebRTC | 媒体节点 → 浏览器 | `rtc`/`rtcs` | 需要 WebRTC 信令与 ICE；仅有 URL 不保证跨 NAT 或 HTTPS 环境可用 |
| 第三方裸 RTP、RTP/PS | 外部媒体服务 ↔ WVP | `/api/rtp/**`、`/api/ps/**` | 先调用 `receive/open` 获得收流端口；区分音视频分轨 RTP 与 PS 复合流 |
| JT1078 / JT808 | 车载终端 → WVP | `/api/jt1078/**` | 仅在 `jt1078.enable=true` 时开放；使用终端手机号和整数通道号，见 6.5 节 |

**网络联调：** API 端口、SIP 端口、RTP 端口范围和媒体协议端口都应由部署方确认。Docker/反向代理环境不能把容器内部地址发给外部客户端。HTTPS 页面不要引用 `http://`/`ws://` 视频地址；使用媒体节点提供的 `https_*`/`wss_*` 字段或现场网关地址。H.265、音频编码及浏览器支持情况由客户端实际验证；通用回退是 H.264 码流。

## 4. 设备、通道与资源发现

|---|---|---|---|
| [GET /api/device/query/devices](routes/get-08dbae62822e.md)（[模块条目](modules/DeviceQuery.md#route-get-08dbae62822e)） | `page`、`count` 必填；`query`、`status`、`accessType` 可选 | `PageInfo<Device>` | 查询独立设备或下级平台，`accessType=DEVICE/PLATFORM` |
| [GET /api/device/query/devices/{deviceId}](routes/get-54be476af1d1.md)（[模块条目](modules/DeviceQuery.md#route-get-54be476af1d1)） | 路径设备国标编号 | `Device` 或 `null` | 查询单个设备 |

| [GET /api/device/query/sub_channels/{deviceId}/{channelId}/channels](routes/get-6a98a4fe432e.md)（[模块条目](modules/DeviceQuery.md#route-get-6a98a4fe432e)） | `channelId` 是父目录国标编号；分页和过滤参数同上 | `PageInfo<DeviceChannel>` | 展开目录 |
| [GET /api/device/query/channel/one](routes/get-5036400fee9a.md)（[模块条目](modules/DeviceQuery.md#route-get-5036400fee9a)） | `deviceId`、`channelDeviceId` | `DeviceChannel` | 查询单个原始通道 |
| [GET /api/device/query/devices/{deviceId}/status](routes/get-dc0ed0f67070.md)（[模块条目](modules/DeviceQuery.md#route-get-dc0ed0f67070)） | 路径设备国标编号 | 设备上报的状态字符串 | 主动向设备查询状态；可能等待设备应答 |
| [GET /api/common/channel/list](routes/get-4a6977eb4970.md)（[模块条目](modules/ChannelController.md#route-get-4a6977eb4970)） | `page`、`count` 必填；`query`、`online`、`channelType`、`civilCode`、`parentDeviceId`、`hasRecordPlan` 可选 | `PageInfo<CommonGBChannel>` | 查询统一通道，取 `gbId`；`channelType=0/1/2` 为国标/推流/代理 |
| [GET /api/common/channel/one](routes/get-5750e8fcf893.md)（[模块条目](modules/ChannelController.md#route-get-5750e8fcf893)） | `id=<gbId>` | `CommonGBChannel` | 查询一个统一通道 |

```bash
curl -sS "$WVP/api/device/query/devices?page=1&count=50&accessType=PLATFORM" -H "api-key: $API_KEY"
curl -sS "$WVP/api/device/query/devices/<deviceId>/channels?page=1&count=100&resourceType=CHANNEL" -H "api-key: $API_KEY"
curl -sS "$WVP/api/common/channel/list?page=1&count=100&channelType=0&online=true" -H "api-key: $API_KEY"
```

`DeviceChannel.channelType` 的 `0/1/2/3/4` 分别是视频通道、行政区划、业务分组、平台节点、普通目录；它与统一列表查询参数 `channelType=0/1/2` **不是同一枚举**。业务上应同时检查 `resourceType=CHANNEL`、`playable=true`、在线状态；目录节点不能直接点播。

成功响应的 `data` 例如：

```json
{
  "app":"rtp",
  "stream":"<服务端返回的流ID>",
  "rtsp":"rtsp://<media-host>:<rtsp-port>/rtp/<stream>",
  "https_flv":"https://<media-host>/rtp/<stream>.live.flv",
  "https_fmp4":"https://<media-host>/rtp/<stream>.live.mp4",
  "https_hls":"https://<media-host>/rtp/<stream>/hls.m3u8",
  "rtc":"https://<media-host>/index/api/webrtc?app=rtp&stream=<stream>&type=play",
  "mediaServerId":"<节点ID>"
}
```

以上只示意字段形状，**不要照抄示例的域名、端口或路径去拼接实际播放地址**。浏览器选 `rtc/rtcs`、`flv/https_flv`、`ws_flv/wss_flv`、`fmp4` 或 `hls` 时，应使用适配播放器并验证 URL 可达、跨域和协议升级。关闭窗口、切换通道或离开页面时调用匹配的 stop 接口；回放有单独的 stop，不能用实时停播代替。

如需截图，[GET /api/play/snap?deviceId=<国标设备号>&channelId=<国标通道号>](routes/get-47b8827727b6.md)（[模块条目](modules/PlayController.md#route-get-47b8827727b6)） 通过点播媒体流生成服务器截图，返回服务器侧文件信息；[GET /api/device/query/snap/{deviceId}/{channelId}](routes/get-900c577f6392.md)（[模块条目](modules/DeviceQuery.md#route-get-900c577f6392)） 读取已保存的图片（二进制，可选 `mark` 指定文件名后缀）。前者生成带时间戳的文件名，后者按固定命名规则取文件，**不能假设调用前者后可直接用后者读到同一张图片**；由部署方确认文件命名或提供统一截图代理后再对外使用。

### 5.1 双向对讲与喊话

## 6. 视频接入：GB28181、RTSP、推流、RTP/PS 与 JT1078

### 6.1 下级 GB28181 平台或设备接入

第三方作为下级平台时，向部署方取得 WVP 的国标平台编号/域、SIP 地址/端口/传输方式、鉴权方式、RTP 收流可达地址和目录共享要求。下级以 REGISTER 注册、Keepalive 保活、Catalog 提供通道；WVP 点播时发 INVITE，设备按 SDP 向媒体节点送 RTP/PS，停播时发送 BYE。云台走 DeviceControl MESSAGE。媒体是否送达应查 RTP 到达与媒体节点，而非只看 SIP 200。

第三方应提供稳定且唯一的设备/通道国标编号，Catalog 中正确标识视频通道和目录，确认 H.264/H.265、音频、PTZ 能力及权限。完成后使用第 4 节接口验证在线状态和可播放资源，再按第 5 节点播。本文不将某个现场固定的 SIP/RTP 端口当作通用约定。

`/api/ps/**` 用于 RTP 承载的 PS 复合流；`/api/rtp/**` 用于视频/音频分轨 RTP。它们是媒体互联接口，必须由双方约定编码、PT、SSRC、传输模式及媒体节点可达性。

| 接口组 | 作用 | 关键参数 |

|---|---|---|---|---|---|

```bash
curl -sS --get "$WVP/api/ps/receive/open" -H "api-key: $API_KEY" \
  --data-urlencode 'isSend=false' --data-urlencode 'callId=<本次会话唯一ID>' \

  --data-urlencode 'callBack=https://<可由WVP访问的回调地址>'
```

RTP 分轨接收时改用 [/api/rtp/receive/open](routes/get-fd96c5f073e3.md)（[模块条目](modules/RtpController.md#route-get-fd96c5f073e3)），分别读取 `receivePortForVideo` 与 `receivePortForAudio`。结束收流用同协议的 `/receive/close?stream=<本次流ID>`，结束向外发流用 `/send/stop?callId=<本次会话唯一ID>`。

#### 按设备批量查询有预置位的通道

[GET /api/front-end/preset/query/{deviceId}](routes/get-45b3877f720f.md) 根据设备国标编号，实时逐个查询设备下全部视频通道，排除目录节点和预置位列表为空的通道。

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `deviceId` | Path | string | 是 | 设备国标编号，不是数据库ID |
| `timeout` | Query | integer | 否 | 整体超时秒数，默认60，允许1–300；单通道最多等待5秒 |

```bash
curl -sS "$WVP/api/front-end/preset/query/<deviceId>?timeout=60" -H "api-key: $API_KEY"
```

成功示例：

```json
{
  "code": 0,
  "msg": "成功",
  "data": [
    {
      "channelId": "34020000001320000001",
      "channelName": "东门球机",
      "presets": [
        { "presetId": "1", "presetName": "入口" }
      ]
    }
  ]
}
```

`data` 为通道数组，`channelId` 为通道国标编号，`channelName` 为通道名称，`presets` 为非空预置位数组。`presetName` 按“平台备注 → 设备名称 → 自动名称”选择。全部查询成功但没有预置位时返回 `code=0, data=[]`。

部分通道失败或未完成时返回 `code=100`，整体HTTP异步等待超时时可返回 `code=408`；`data` 可能包含已成功查询到的非空通道，`msg` 提示结果不完整。**只有 `code=0` 才能用于全量同步，不能根据部分结果删除已有预置位。** 整体超时后不再发起后续通道查询；通道较多时可适当增加 `timeout`。

#### 编号与平台名称备注

| 字段 | 位置 / 适用接口 | 类型 | 必填 | 格式 / 范围 | 默认值 / 未传行为 | 说明 | 示例 |
|---|---|---|---|---|---|---|---|
| `deviceId` | 直连接口Path | string | 是 | 设备/下级平台国标编号；使用资源接口原值 | 无 | 目标设备 | `<deviceId>` |
| `channelId` | 直连接口Path | string | 是 | 通道国标编号；使用资源接口原值 | 无 | 不能传数据库整数ID | `<channelId>` |
| `channelId` | 统一接口Query / Form | integer | 是 | 通道数据库整数ID（gbId） | 无 | 不能传国标通道编号 | `123` |
| `presetId` | 设置/调用/删除Query；修改名称Query / Form | string或整数形式的HTTP参数 | 是 | 十进制1–255；兼容PresetID_1至PresetID_255；0号预留 | 无；无效编号返回code=100 | 预置位编号；未知字符串不可截取末尾数字后控制 | `1` |
| `presetName` | 设置Query；修改名称Query / Form | string | 否 | 去除首尾空白；最多128个UTF-16编码单元；普通汉字通常各占一个，部分Emoji占两个 | 未传或空白生成“预置点+编号”；过长code=400 | 平台位置/标志备注，不写入国标指令 | `东门入口` |

查询模型中的编号为字符串；已知别名规范化为数字字符串，其他非标准编号保留用于展示。以下是备注保存与显示规则：

- 名称备注保存在数据库，按通道和预置位编号隔离；刷新页面、重启服务及切换入口后保留。查询返回的 `presetName` 按“平台备注 → 设备返回名称 → 自动名称”选择。
- 设置接口只有在设备返回 SIP `200 OK` 后才保存备注；拒绝或超时不会覆盖已有备注。修改名称接口仅更新平台备注，不下发云台指令，不改变预置位位置；留空保存会恢复“预置点+编号”，不会恢复设备名称。
- 设备接受删除指令后删除对应备注。备注记录不代表设备存在该预置位；查询列表以设备返回的预置位为准，不会因平台保存了备注而新增条目。

#### 设置、调用、删除与修改名称示例

设置位置并填写平台名称（`--data-urlencode` 正确编码中文）：

```bash
curl -sS --get "$WVP/api/front-end/preset/add/<deviceId>/<channelId>" \
  -H "api-key: $API_KEY" \
  --data-urlencode 'presetId=1' --data-urlencode 'presetName=东门入口'

# 未传 presetName 时，平台保存默认名称“预置点2”
curl -sS --get "$WVP/api/common/channel/front-end/preset/add" \
  -H "api-key: $API_KEY" --data-urlencode 'channelId=123' --data-urlencode 'presetId=2'

curl -sS "$WVP/api/front-end/preset/call/<deviceId>/<channelId>?presetId=1" -H "api-key: $API_KEY"
curl -sS "$WVP/api/front-end/preset/delete/<deviceId>/<channelId>?presetId=1" -H "api-key: $API_KEY"
```

上述设置、调用、删除的成功响应：

```json
{"code":0,"msg":"设备已接收预置位指令","data":null}
```

仅修改已有预置位的名称（表单或 URL 查询参数绑定，**不使用 JSON body**）：

```bash
curl -sS -X POST "$WVP/api/front-end/preset/remark/<deviceId>/<channelId>" \
  -H "api-key: $API_KEY" \
  --data-urlencode 'presetId=1' --data-urlencode 'presetName=路口北侧'

curl -sS -X POST "$WVP/api/common/channel/front-end/preset/remark" \
  -H "api-key: $API_KEY" \
  --data-urlencode 'channelId=123' --data-urlencode 'presetId=1' --data-urlencode 'presetName=路口北侧'
```

两种入口的修改成功响应相同：

```json
{"code":0,"msg":"成功","data":"路口北侧"}
```

若把 `presetName` 设为空字符串或省略，修改接口成功响应的 `data` 为“预置点1”。修改名称接口不检查设备是否存在该编号，也不会新建设备预置位，调用前应先查询设备列表。

#### SIP 应答和错误处理

设置、调用、删除使用国标 `DeviceControl` / `PTZCmd`，指令分别为 `81H`、`82H`、`83H`，第 5 字节为 `00H`，第 6 字节为编号；平台名称不进入国标控制指令。

仅收到当前 MESSAGE 的 SIP `200 OK` 才返回 `code=0`；跨节点时也由设备所属节点等待应答后返回。无需等待另一条 DeviceControl XML 执行结果。成功表示**设备已接收指令**，应通过画面或重新查询核实实际动作，不能当作镜头到位或永久保存的确认。删除全部预置位需要逐项删除，没有新增国标“清空”指令。

| 情况 | 业务 `code` | 处理 |
|---|---|---|
| SIP 拒绝 | 设备返回的 SIP 状态码，如 `403` | 展示 `msg`；业务码与 HTTP 状态码分开判断 |
| SIP / 跨节点应答超时 | `408` | 未确认设备接收，可能已执行；先核实设备状态，不自动重复下发 |
| 发送失败 | `100` | 展示实际 `msg` |
| 设备已接收，但平台备注保存失败 | `100` | `msg` 明确说明设备已接收；刷新列表后使用修改名称接口补存，不重新设置位置 |
| 名称超过长度限制 | `400` | 修正名称后提交 |

超时示例：

```json
{"code":408,"msg":"预置位指令应答超时，未确认设备接收，请刷新设备状态后重试","data":null}
```

控制接口虽然使用 GET，仍具有副作用，不能按普通读请求在网络错误后自动重试。修改名称是 POST，保存成功只表示平台备注写入成功。

#### 第三方同步全部预置位（按通道）

查询接口每次向设备/下级平台查询指定通道当前的预置位列表，不分页，并合并平台名称备注。跨通道同步须遍历通道逐个查询。平台修改名称后，第三方重新调用查询接口即可获取最新显示名称；设备新增或删除的编号还需等待设备查询结果反映变更。

```bash
curl -sS "$WVP/api/front-end/preset/query/<deviceId>/<channelId>" -H "api-key: $API_KEY"
curl -sS "$WVP/api/common/channel/front-end/preset/query?channelId=123" -H "api-key: $API_KEY"
```

成功响应示例：

```json
{
  "code": 0,
  "msg": "成功",
  "data": [
    {"presetId": "1", "presetName": "东门入口"},
    {"presetId": "2", "presetName": "预置点2"}
  ]
}
```

| 响应字段 | 类型 | 可空 / 出现条件 | 格式 / 取值 | 说明 | 示例 |
|---|---|---|---|---|---|
| `data[].presetId` | string | 设备返回该预置位时读取 | 已知别名规范化；其他编号保留展示，控制前校验 | 通道内同步主键 | `"1"` |
| `data[].presetName` | string | 设备返回该预置位时读取 | 平台备注→设备名称→自动名称 | 最终显示名称，不保证是设备端名称 | `"东门入口"` |

接口不返回角度、地理坐标、修改时间、版本号或修改人，也不提供变更推送或增量游标。名称中的位置/标志信息是用户输入的文字，不代表设备提供了定位数据。

1. 按设备和通道隔离数据，以 `(deviceId, channelId, presetId)` 或 `(gbId, presetId)` 为主键。
2. 仅在 HTTP 成功、`code=0` 且 `data` 是数组时更新名称和新增项；成功空列表为 `data=[]`。
3. 只有确认设备支持完整预置位查询后，才能用成功快照删除本地多余项；分包未收齐时不返回成功的残缺列表。查询失败、超时、备注读取失败或 `data=null` 时，保留上次数据并提示实际 `msg`。
4. 同一通道避免并发同步，防止旧请求覆盖新数据；设备未在线或不支持查询时无法获得有效快照。

查询超时示例：

```json
{"code":100,"msg":"预置位查询超时，请检查设备在线状态及是否支持预置位查询","data":null}
```

查询超时也可能返回设备订阅错误码 `486` 等；不要与控制接口的 `408` 或查询成功空列表混淆。

#### 兼容 API

[GET /api/v1/control/preset](routes/get-2f4adbe0e7d7.md)（[模块条目](modules/ApiControlController.md#route-get-2f4adbe0e7d7)） 的兼容参数如下：

## 10. 完整对接流程与故障定位

### 10.1 最小实时播放流程

1. 获取凭证和部署方的 API 根地址。
2. [GET /api/device/query/devices](routes/get-08dbae62822e.md)（[模块条目](modules/DeviceQuery.md#route-get-08dbae62822e)） 或 [GET /api/common/channel/list](routes/get-4a6977eb4970.md)（[模块条目](modules/ChannelController.md#route-get-4a6977eb4970)），确认设备在线；从统一列表取整数 `gbId`。
3. 若按设备目录查询，选 `resourceType=CHANNEL` 且 `playable=true` 的视频通道。
4. [GET /api/common/channel/play?channelId=<gbId>](routes/get-5d1a5ef7abf5.md)（[模块条目](modules/ChannelController.md#route-get-5d1a5ef7abf5)）；同时检查 HTTP 状态、`code` 和 `data`。
5. 按客户端能力选择响应中非空的播放 URL，验证媒体端口、编码、HTTPS/WSS 与 WebRTC ICE。
6. 关闭画面时调用 [GET /api/common/channel/play/stop?channelId=<gbId>](routes/get-0b07595beddb.md)（[模块条目](modules/ChannelController.md#route-get-0b07595beddb)）。

### 10.2 预置位流程

先查询预置位；选一个已与设备确认的 1–255 整数，调用设置/调用/删除；查询列表并观察画面确认结果。查询返回的 `presetId` 按原字符串保存；控制接口兼容 `PresetID_1` 至 `PresetID_255` 这类已知格式。未知字符串保留用于展示和排错，不截取尾数后强行控制。新增时需检查编号冲突；设备已使用的编号可能并非平台能直接识别的数字。

### 10.3 常见故障

| 现象 | 优先检查 |
|---|---|
| HTTP 401/403 | JWT/API Key 是否有效、角色是否有控制权限、现场是否启用了鉴权 |
| HTTP 200 但 `code != 0` | 读取 `msg`；设备离线、超时、参数不符或媒体节点异常都可能出现 |
| 设备存在但看不到视频 | 目录项是否被当作视频通道；`resourceType`、`playable`、在线状态和下级 Catalog |
| 点播成功但播放失败 | 媒体 URL 是否可达、外部端口映射、编码、跨域/HTTPS、WebSocket 101、WebRTC ICE 与 RTP 是否到达 |
| 预置位能显示但调用失败 | 查询ID按字符串保留；控制支持1–255及已知PresetID_N格式；未知字符串不可截尾取数字 |
| RTSP 拉流失败 | 源地址/凭证、WVP 到源的网络、TCP/UDP 模式、编码与媒体节点日志 |
| 云端录像列表有数据但地址打不开 | `remoteHost` 是否含协议和外部端口、媒体文件是否仍存在、下载权限与网关路径 |
