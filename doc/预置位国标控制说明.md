# 预置位国标控制说明

## 指令格式

按 GB/T 28181 附录 A.3.1、A.3.4 表 A.8 生成 8 字节 PTZCmd：

| 操作 | 字节4 | 字节5 | 字节6 |
| --- | --- | --- | --- |
| 设置 | 81H | 00H | 01H–FFH |
| 调用 | 82H | 00H | 01H–FFH |
| 删除 | 83H | 00H | 01H–FFH |

预置位编号为 1–255，0 号预留；名称不进入预置位控制指令。字节8为前7字节之和的低8位。例如调用1号预置位生成 `A50F018200010038`。

控制使用 SIP MESSAGE，Content-Type 为 Application/MANSCDP+xml，XML 根节点为 Control，CmdType 为 DeviceControl，DeviceID 使用设备原始通道国标编号，控制码放在 PTZCmd 中。

## 接口与应答

设备入口 `/api/front-end/preset/{add|call|delete}/{deviceId}/{channelId}` 和通用通道入口 `/api/common/channel/front-end/preset/{add|call|delete}` 统一使用同一套国标预置位服务。

兼容入口 `/api/v1/control/preset` 的 set/goto/remove 也进入同一服务。必须通过 code 指定目标通道，当前没有可用的通道序号映射，不能只传 channel；name 用于保存平台名称备注，不下发设备。

- 只有收到设备对本次 MESSAGE 的 SIP 200 OK，接口才返回 code=0，表示“设备已接收预置位指令”。
- SIP 拒绝保留设备响应状态码及原因；发送失败返回非零错误码；SIP 或跨节点等待超时返回 code=408。
- 云台控制不等待另一条 DeviceControl XML 执行结果应答。SIP 200 OK 也不能作为镜头已到位的证据。
- 设备位于其他节点时，由所属节点等待 SIP 应答后返回 Redis RPC 结果；所有节点需同时更新以支持新增的 channel/ptz/preset RPC 路由。
- 前端禁止预置位添加、调用、删除请求在网络错误后自动重试。超时代表未确认设备接收，设备可能已经执行，应先核实设备状态。
- 清空预置位仍逐项下发标准删除指令，收到应答后重新查询设备列表，不直接把本地列表置为空。

## 平台名称备注

添加预置位时可填写最长128个字符的名称备注，例如“东门入口”“路口北侧”。空白名称自动生成“预置点+编号”。只有设备接收添加指令后才保存备注；拒绝或超时不会覆盖已有备注。

设备管理与通用通道管理均可通过“修改名称”修改已有预置位的备注，该操作只保存平台数据，不下发云台指令，也不改变预置位位置。留空保存会恢复默认名称。

设备入口的修改接口为 `POST /api/front-end/preset/remark/{deviceId}/{channelId}`，通用通道入口为 `POST /api/common/channel/front-end/preset/remark`；均使用请求参数 presetId、presetName，通用入口还需 channelId。

备注以通道数据库ID和预置位编号作为组合键，保存到独立表 wvp_preset_remark。平台查询预置位时，显示顺序为“平台备注 → 设备名称 → 自动名称”。设备查询没有返回的预置位不会因为平台保存了备注而出现在列表中。所有现有查询界面（包括实时预览和巡航选择）共用同一查询结果。

系统启动时自动检查并创建备注表，不修改原有设备表。若部署账号没有建表权限，可由数据库管理员提前执行 `src/main/resources/db/preset-remark.sql`。共享同一数据库的节点会读取同一份备注；刷新页面和重启服务不会清除备注。设备接收删除指令后会删除对应备注。

## 验证范围

回归测试覆盖三种操作的 765 组编号编码及校验和、实际 MESSAGE/XML 封装、原始通道编码、SIP 100/200/202/401/403、发送异常、超时与迟到应答、HTTP 异步返回和 Redis RPC 应答传播。前端测试覆盖编号转换、无效编号、控制请求不自动重试，以及添加名称、修改名称和刷新列表。备注测试还覆盖数据库持久化、通道隔离、默认名称、长度限制与保存失败。

上述为自动化验证；部署后仍需使用实际设备抓包，核对 DeviceID、PTZCmd、设备 SIP 应答及镜头动作。
