# 宇视 GB28181 平台级联对接信息

文档版本：V1.0  
编制日期：2026-09-16  
对接方式：GB/T 28181 平台级联

## 一、对接关系

本项目视频接入平台作为 **GB28181 上级平台**，宇视视频管理平台或宇视 NVR 作为
**GB28181 下级平台**，由宇视侧主动向我方平台注册。

```text
宇视视频管理平台/NVR（下级平台）
        │ REGISTER、Keepalive、Catalog、Invite、DeviceControl
        ▼
指挥调度视频接入平台（上级平台）
```

本次建议以宇视平台或 NVR 为单位进行级联，由宇视侧统一上报授权范围内的设备目录，
不需要逐台摄像机分别对接。

| 我方 → 宇视 | 宇视回传的 SIP 地址 | UDP/宇视 SIP 端口 | Catalog、Invite、DeviceInfo、DeviceControl |
| 宇视 → 我方 | `10.73.191.167:10000` | UDP/TCP | 实时视频 RTP/PS，最终以 SDP 为准 |

双方网络必须双向可达，并确保防火墙、安全设备和 NAT 不修改 SIP 报文中的国标编号、
Contact、Via 或 SDP 地址。若存在 NAT，请宇视明确提供信令出口和媒体出口转换关系。

## 五、注册和业务交互要求

1. 宇视侧向 `10.73.191.167:8116` 发送 REGISTER。
2. 本次不启用 Digest 认证；我方完成下级平台编号预置后，合法 REGISTER 应直接收到
   `200 OK`，正常情况下不会先收到 `401 Unauthorized`。
3. 宇视侧按约定周期发送 Keepalive，并在注册到期前发送续订 REGISTER。
4. 注册在线后，我方发送 Catalog 查询，宇视侧上报审批范围内的设备和通道目录。
5. 点播时我方向宇视发送 INVITE；宇视侧根据 SDP 指定的地址、端口和传输方式发送 RTP/PS。
6. 停止点播时双方完成 BYE 交互并释放媒体资源。
7. 若已授权 PTZ，我方通过 DeviceControl 下发方向、变倍和停止指令。

## 六、联调顺序及验收标准

建议按以下顺序逐项确认：

1. **网络连通**：双方 SIP 地址和端口双向可达。
2. **平台注册**：宇视 REGISTER 收到 `200 OK`，我方页面显示设备在线。
3. **心跳保活**：连续观察不少于 10 分钟，平台不应反复上下线。
4. **目录同步**：我方能够查询并获得完整设备、通道名称和唯一国标编号。
5. **单路点播**：选择 1 路 H.264 通道完成 INVITE、RTP 收流和浏览器播放。
6. **并发点播**：根据审批范围验证多路同时播放。
7. **停止点播**：BYE 后宇视侧停止发送媒体流，资源正常释放。
8. **云台控制**：对有权限的球机验证上下左右、变倍和停止指令。
9. **异常恢复**：验证网络中断、宇视服务重启后的自动重新注册和目录恢复。

验收通过的基本标准：注册稳定、心跳正常、目录完整、通道编号唯一、视频可播放、停止后不残留
媒体流，且授权 PTZ 指令能够正常执行。

## 七、常见状态码说明

| 状态码/现象 | 含义 | 建议处理 |
|---|---|---|
| `200 OK` | 注册或请求成功 | 继续进行心跳、目录和点播验证 |
| `400 Bad Request` | REGISTER 缺少必要字段或报文格式错误 | 检查 Expires、From、Contact、Via、CSeq |
| `401 Unauthorized` | 我方实际运行配置启用了 Digest 认证 | 暂停联调，由我方核对认证配置；不要反复尝试密码 |
| `403 Forbidden` | 下级平台编号未预置、编号不合法或不在授权范围 | 核对宇视下级平台国标编号并联系我方完成白名单预置 |
| 注册无响应 | 地址、协议、端口或网络策略不通 | 抓包并检查 `10.73.191.167:8116/UDP` 双向路由和防火墙 |
| 注册在线但无目录 | Catalog 未响应或目录未授权 | 检查宇视共享范围、目录订阅及通道编码 |
| 有目录但无视频 | INVITE/SDP 或 RTP 路由问题 | 检查媒体出口、`10000` 端口及 H.264/PS 配置 |
